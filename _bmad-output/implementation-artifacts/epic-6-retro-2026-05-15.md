## Challenges

### 1. Bayesian P(A>B) — subtle mathematical edge cases

`calculatePAGreaterThanB` in `trafficLight.ts` required 5 non-trivial code review fixes:
- Missing guard for `numA > denomA` → NaN propagation to UI ("NaN% confident")
- Degenerate case `sigma === 0` with `muA === muB` → was returning 0 (displayed "100% confident B is better")
- Threshold `> 0.70` should be `>= 0.70` (AC says 70–95% inclusive)
- Contradictory tooltip: red non-null confidence was showing "Données insuffisantes" label (tooltipNoData) while tooltip said "X% confident" → `tooltipLowConfidence` key introduced
- `TrafficLightResult.confidence` range documented as 0.0–1.0 (wrong) → corrected to 0.5–1.0 (because `max(p, 1-p) >= 0.5`)

**Pattern:** Statistical code has no compiler errors — everything "works" but results are silently wrong. This class of bug is hard to spec and only reviewable with deep domain understanding.

### 2. Timezone handling — missed in spec, caught in review

`interactionsThisWeek` and `interactionsThisMonth` in Story 6.8 used `DateTime.now()` on the server (UTC), but "this week" from a French user's perspective starts on Monday at 00:00 Paris time — not UTC. Code review caught this and added a `tz` query param with client-side `Intl.DateTimeFormat().resolvedOptions().timeZone`.

**Pattern:** Any feature involving "current week / month / day" must consider the client timezone. A spec-level checklist question: "Is this relative to server time or user time?"

### 3. E2E brittle `getByText()` — strict mode violations

Story 6.8's `DashboardSummary` added funnel stage names in the "Funnel Overview" section. Playwright's strict mode (`getByText('Lead qualified')`) now finds 2 elements: the FunnelCard accordion trigger AND the funnel overview row. This broke 3 existing E2E specs.

**Fix:** Scope locators to `[data-slot="accordion-trigger"]` instead of bare `getByText()`.

**Pattern:** When a new component renders text that already appears elsewhere in the page, strict-mode Playwright locators break. Prefer attribute-scoped or role-based selectors over bare `getByText()`.

### 4. Human acceptance testing was light during this epic

Romain was minimally involved during story implementation — the agent-driven development model means human in-the-loop validation is thinner than in a traditional team. Individual features were checked as blocks, but no global end-to-end recettage was done.

**This is the primary pre-production gate remaining.**

### 5. VineJS global migration bundled opportunistically

`vine.compile()` → `vine.create()` was a pending housekeeping change bundled into Story 6.5. 8 backend validators + 6 frontend schemas modified in one commit, mixed with the battle management feature. Clean result, but noisy diff.

## Key Insights

1. **The review process is the intended last net — don't remove it.** It caught everything from mathematical edge cases to timezone bugs to E2E test design issues. The philosophy "you can't think of everything upfront, that's what reviews are for" is correct. The key invariant: never skip the review.

2. **Architectural discipline compounds.** Every "boring" decision made early — `forUser` scope, shared types, serializers, feature-based org — paid dividends across 8 stories without re-discussion. Good architecture isn't visible when it works, only when it doesn't.

3. **Statistical code needs extra scrutiny.** The Bayesian logic is a class of code where "the tests are green" doesn't mean "the results are correct." The only effective safeguard is review by someone who understands the math. Consider adding unit tests for `calculatePAGreaterThanB` as a long-term improvement.

4. **Agent-driven development shifts the validation contract.** The agent implements, tests pass, review catches bugs — but the human's role as acceptance tester is more concentrated (recettage global) rather than distributed (day-to-day review). This is a known tradeoff, not a problem, but the recettage must happen.

5. **MVP complete — roadmap transition needed.** With Epics 1–7 done and Epic 8 deprioritized, BattleCRM is at a pivot point: from "build the planned features" to "ship to production and discover what's next." This requires a different planning mode than epic-by-epic execution.
